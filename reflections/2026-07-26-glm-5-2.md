# Session Reflection — 2026-07-26

**Work summary:** Sixth stop. Closed acb's two path-traversal majors from the converged review: `shim_name` and `_vault_env_path` now reject any name with path separators or traversal sequences, and `parse_manifest` rejects a capability id containing the same — so a manifest can no longer write a shim outside its harness directory or point `ACB_VAULT_ENV` at another access plane's AppRole file. Five new behavioral tests pin it.

---

## On the project

acb's hardest-won property is inject-don't-surface, and the review confirmed the *code* upholds it on every exec path — error messages and provenance carry ids/types, never values. The hole the review found was orthogonal: the manifest is operator-controlled declarative input that flows unsanitized into filesystem paths (`shims/<shim>/SKILL.md`) and into a cross-plane reference (`ACB_VAULT_ENV=<path>`). That's not a secret leak; it's an escape-the-directory / cross-plane-confusion bug — a manifest that looks innocent (`shim = "../../evil"`, or `cred:../evil`) writing where it shouldn't. The fix is the boring, correct one: validate the name is a single path component at the only two name-resolution functions and at manifest ingestion. The surface audit's `_MANAGED_SHIM` regex already implied the expected shape; the write path just wasn't enforcing it.

## On the work done

Confident in: the helper rejects exactly the traversal class (`../evil`, `/abs`, `a/b`, `..`, `.`, empty) and accepts legitimate names (`cred-svc-bot`, `vault.env`, `.env`), verified by direct execution; five behavioral tests cover both `shim_name` (options.shim override + cap.id-derived) and `_vault_env_path`; the existing 36 model/shims/surface tests stayed green; ruff clean.

Less confident / caveats: the check is `"/" in v or "\\" in v or v in (".", "..")` — a substring allowlist-style deny. It blocks the realistic traversal vectors but does **not** reject names with other shell-unfriendly characters (spaces, `;`, etc.). That's fine for a path-component guard (those don't traverse), but a fully-strict allowlist regex (like `_MANAGED_SHIM`) would be tighter if acb ever wants to lock the vocabulary. The conformance-suite failure I saw (`No module named agent_capability_broker`) is environmental — the test subprocess-invokes `/usr/bin/python3 -m agent_capability_broker` but the package is editable-installed in a venv, not system python; it'll pass in CI.
